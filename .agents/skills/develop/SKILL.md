# 标准开发流程

1. 执行 `git status`、`git diff`，确认当前分支和未提交变更。保留用户已有变更；归属不明且会影响切分支时先询问。
2. 从本地 `master` 创建任务分支：功能使用 `codex/feature-<name>`，修复使用 `codex/fix-<name>`。如果已经位于本任务的正确分支，直接继续。
3. 检查仓库约束和相关实现，完成最小范围修改，不夹带无关重构。
4. 检查完整 diff，先运行相关测试，再运行仓库发布检查 `pnpm release:check`。失败时修复后重新验证。
5. 根据变更职责合理拆分提交；提交信息清晰，合并前确保工作区干净。
6. 切回 `master`，使用 `--no-ff` 合并任务分支。发生不属于本任务的冲突时停止并说明。
7. 保留本地任务分支，不删除；除非用户明确要求，否则不推送远端。
8. 最终报告任务分支、提交、合并提交和验证结果。

只读分析、代码审查和问题诊断不创建分支、不提交也不合并，除非用户同时要求修改。
